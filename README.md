# PICO (피코)

![PICO 공연 티켓 예매 도우미 매칭 플랫폼 배너](assets/pico-banner.png)

**공연·이벤트 티켓을 예매하려는 이용자와 예매를 도와줄 도우미를 연결하는 매칭 플랫폼**
https://pico-kr.app/

멋쟁이사자처럼 데모데이에서 진행한 팀 프로젝트입니다. 원하는 티켓을 직접 예매하기 어려운 이용자가 도우미를 찾고, 희망 좌석과 예매 성공 조건을 전달한 뒤 결과와 증빙까지 확인할 수 있도록 설계했습니다.

## 주요 흐름

1. **도우미 탐색** — 프로필과 경력 정보를 보고 예매를 맡길 도우미를 찾습니다.
2. **요청 및 조건 합의** — 예매처, 희망 좌석, 성공 조건을 요청서에 담아 보내고 도우미와 최종 조건을 조율합니다.
3. **예매 결과 확인** — 도우미가 등록한 예매 결과와 증빙을 확인합니다. 필요한 경우 문의나 분쟁 절차로 이어집니다.

## 내 기여

### 백엔드 개발

- **회원 관리 및 도우미 검색** · Spring Boot로 회원 관리, JWT 인증, 도우미 프로필과 검색 기능을 개발했습니다.
- **예약 검색 개선 및 AI 호출 비용 최적화** · KOPIS API로 실제 공연 정보를 연동하고, 해당 예매처를 지원하는 도우미를 찾도록 검색을 개선했습니다. 기본 검색에서 후보가 없을 때만 AI로 검색어를 보정하고, 예매처까지 확인된 별칭은 14일간 저장했습니다. 반복 검색에서 저장된 별칭을 재사용해 AI를 다시 호출하지 않도록 했습니다.
- **AI 사전 검토** · Liner AI를 연동해 예매 요청서를 검사하고, 도우미의 경력 설명과 증빙 사진을 비교했습니다. 판단이 어려운 항목은 관리자에게 표시하고, 최종 승인은 관리자가 맡도록 했습니다.
- **DB 변경 관리** · Flyway로 DB 스키마 변경 이력을 관리하고, 팀 브랜치 통합 과정에서 마이그레이션 충돌을 해결했습니다.

### 서버 운영 및 데이터 분석

- **EC2 운영 점검 및 접속·가입 추이 분석** · EC2에 SSH로 접속해 Caddy, Spring Boot, MySQL의 실행 구성과 보안 그룹의 SSH 접근 범위를 확인하고, CloudWatch에서 일주일간 CPU 사용률·네트워크·CPU 크레딧을 점검했습니다. Caddy 로그에서 일별 고유 IP 수와 전체 화면 요청 수를 집계하고, 운영 DB의 가입 데이터와 비교해 **일반 회원 가입 47건 중 34건이 11월 1~8일에 집중**된 것을 확인했습니다.

### 출시 준비 및 운영

- **법률 자문과 도우미 모집** · 출시 전 결제 심사, 이용약관, 분쟁 처리에 관한 질문을 정리해 후속 법률 자문을 요청했습니다. 출시 후에는 현업 도우미에게 직접 연락해 입점을 제안하고, 기존 거래 경험을 PICO 프로필에 보여줄 수 있도록 제출 자료를 안내했습니다.
- **데모데이 사업 검증** · 현장에서 모의투자 참가자를 모집해 서비스를 소개하고 참여를 이끌었습니다. 팀은 모의투자대회에서 15개 팀 중 3위를 기록했습니다.

## 구현 및 데모

팀 프론트엔드는 React, TypeScript, Vite로 구성되며, OpenAPI 명세를 기준으로 백엔드 API와 연동합니다. 개발용 데모 모드에서는 결제와 본인인증 등 일부 단계의 응답을 모의 처리합니다.
